# 产品总纲

当前交付方式：助手逐版开发并提供设计与验证说明；教学课程保留参考。V0.4 已实现多 Agent、审批恢复、设备绑定、授权本地工具及新工作台，服务器供本人经 SSH 隧道验证；公网内测仍待 V0.5。

## 目标

做一个可以邀请少量真实用户使用的个人多 Agent 工作台。用户登录后提出任务、讨论需求、查看计划和执行过程、处理授权、获取结果，并管理属于自己的设备。不是围绕 GitHub 事件或代码开发流程的系统。

分层调用关系：

```text
浏览器
  → Django：身份、资源归属、业务任务、设备、事件查询
    → 独立 Agent Worker：DeepAgents / LangGraph、模型和工具调用
      → 工具请求记录
        → 主动连接云端的本地客户端：授权目录、受控工具、结果回传
```

云端记录和模型执行不依赖网页存活。没有连接设备时仍可讨论和规划；需要本地能力才等待设备。工具结果如何送入云端模型，必须让用户知情。

## 技术路线

- Python 3.12、uv；Django 5.2 LTS 负责应用层。
- DeepAgents / LangGraph 负责执行图、工具循环和后续子 Agent；不重新实现另一套模型循环。
- PostgreSQL 保存业务数据、队列领取；LangGraph checkpoint 保存执行状态。业务记录不等于 checkpoint。
- 独立 Worker 执行长任务，初期不引入 Celery、Redis 或微服务。
- React + TypeScript + assistant-ui，同源 Session / CSRF；Django 仍是状态事实来源。

DeepSeek Harness 是执行平台参考，SuperAgent 是其上层编排应用参考。本项目不 fork 整套 TypeScript 平台；借鉴任务、授权、派工、跟进和结果交付机制。

## 第一版边界

面向 2—5 位邀请用户，低并发运行。首批工具选择可控的轻量任务，暂不开放任意 Shell、浏览器自动化、GitHub 自动接单。GPU 与后训练不作为上线依赖。云服务器先按 2 核 2 GB 测量，再调整容量。

数据模型从建立起带 owner；登录不能替代任务、设备、附件、审批、事件的逐项归属检查。本地客户端不开放入站端口；绑定凭证可撤销，目录和工具授权均明确列出。

## 完成标准

一次任务能从提交、规划、执行、授权到结果交付；设备断开、进程重启、失败和取消都有准确状态。完成跨用户越权测试、配额控制、备份恢复演练后才邀请内测。不把月底时间表当作已完成承诺。
