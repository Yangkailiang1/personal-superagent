## 真实本机执行器

测试使用两个独立配置目录、设备绑定凭证、本机 checkpoint、SQLite 账本和子进程，经真实 HTTP 领取不同任务。路由通过真实 Worker 子进程，云端 Worker 拒绝领取本机任务。两个客户端并发执行，等待审批时退出子进程、释放额度；批准后恢复原 checkpoint，最终生成云端文档并上传持久化事件。

这证明单机双实例协议与执行链路，不等于两台物理机器的网络/断电验收。真实本机模型、跨机器及 Linux/WSL2 实机尚未验证；macOS 实测，原生 Windows 不支持本版安全文件工具。

## 实测修复

- 设备事件写入后游标记录使用旧 event_seq 引发唯一键冲突：刷新已锁定 Attempt 的序号后同事务写游标。
- 旧看板只检查 V0.5 Confirmation，导致已发布 Plan 仍显示待确认：同时检查 Release 版本。
- 知识建议结果包含系统调用次数元数据，严格 schema 校验拒绝：分离元数据后校验正文。
- langchain-mcp-adapters 与自动解析到的 MCP 2.x 导入不兼容：实测锁定 MCP 1.30.0，并验证工具发现与调用桥接。
- 设备事件与结果先落盘；独立心跳不被模型输出或图片上传阻塞。撤销目录时工具读取不含 token 的即时权限快照。

## 真实服务与限制

实际付费模型、Tavily 和生图请求为 0；MCP 测试使用固定服务响应，未访问真实外部服务。凭证独立配置入口已提供，缺配置明确不可用；不能据此声称已验证真实模型、搜索质量、图像生成效果或任意 MCP 服务兼容性。

巡检默认关闭，仅用户开启后运行；最多八次模型请求，不补跑旧日期，不自动修改正式知识或发布任务。用户自有 Key 的账单不能由云端全面控制。

未知结果不自动重放，人工停止确认不是独立验证。Wiki 文本匹配不是向量检索，知识内容仍需人工审查。当前为 SSH 本人验证部署，公网 HTTPS、邀请配额和正式备份恢复演练仍待内测版。按提交备份和发布不代表数据库能自动回滚。
