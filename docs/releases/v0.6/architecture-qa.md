# V0.6 架构问答

**为什么有路由 Agent 还要服务端排序？** 模型可以解释任务语义和推荐，但设备权限、用户归属、依赖与额度是确定性规则。候选由服务端产生，模型不能发明另一个用户的设备；落地时再次验证。

**为什么不是每台设备一套业务数据库？** 业务任务和发布授权以云端 PostgreSQL 为准，本机只保存执行 checkpoint、私密配置及回执账本。避免两套待办状态互相覆盖。

**怎么继承历史职责？** 稳定 AgentProfile 身份、同一需求会话任务线、带来源的历史摘要和依赖交付。不会把旧图 checkpoint 直接当新任务上下文，也不默认读用户全部会话。

**断线重试如何避免重复写？** started/结果/outbox 均先落盘，副作用前扣预算，重连只重发。无法证明操作结果就保持未知；不声称通用 exactly-once。原生审批和新建不覆盖进一步限制风险。

**巡检能否自己接新任务？** 不能。它只能报告阻塞和未整理材料，任务发布及知识修订确认由用户执行。日级幂等键和八次请求上限控制自动循环。

**Wiki 是否等于向量数据库？** 不等于。当前采用带来源的规范页、修订和索引，查询是受限文本匹配。事实是否正确仍需来源与人工评审；未引入未经评估的 embedding 系统。

**这是安全沙箱吗？** 本机固定工具提供目录和权限约束，不是完整 OS 沙箱。MCP 服务、用户本机程序和 Key 仍属于可信配置，不能保证防御同一 OS 用户修改客户端。
