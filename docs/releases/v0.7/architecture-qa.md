# V0.7 架构问答

**为什么不用 Happier 完整服务？** 用户选择保留一套账号、任务与知识库。复用其本机执行生命周期，避免再同步一套云端会话事实；代价是维护固定提交的派生代码。

**为什么还有 TypeScript？** Claude 执行层上游是 TypeScript，少量侧车直接复用；Django 继续承载业务，Python supervisor 继续承载已有设备协议。没有增加云端 Node 服务。

**如何避免重复执行？** PostgreSQL Task/Attempt 唯一活动约束与领取锁防双领；本机先持久化启动意图，重启不重放；事件带游标，最终回执有摘要，token+instance 拒绝旧执行。不能证明外部副作用 exactly-once，因此不自动重派未知结果。

**审批怎么避免竞态？** 决策属于明确运行和工具 ID，版本校验与幂等键在短事务内处理。网络传输与用户决定不同步，页面显示“等待本机确认”，收到 applied 才认为生效。取消与租约失效使旧决定不可执行。

**为什么审批不释放名额？** 不能可靠证明供应商进程及其活动都暂停。保守保留额度，比出现未统计的并行执行准确。后续只有加上明确暂停协议和证明才优化。

**如何保护真实仓库？** 从已有提交创建 worktree，不复制用户未提交文件，不更新原分支，不合并/push。文件工具检查范围，回收再次检查。但 worktree 共用 Git 元数据，经批准 Shell 并不受安全沙箱隔离。

**为什么不根据最终文字判断成功？** backend 必须收到 SDK 明确 result；系统还要求配置检查齐全且退出码为零、无范围违规。报告明确来自本机，不等同独立测试服务证据，也不等同需求全部验收。

**如何控制成本？** 本机 SDK turn 上限、超时和全局并发是实际实现。供应商可能在一 turn 内产生多次调用，用户 Key 还可能被其他进程使用，不能宣称精确全账户账单上限。没有真实模型调用就不报告成功率、性能或费用数据。
